# 辦公室六格漫畫編排遊戲設計

- 日期：2026-07-27
- 狀態：口頭設計已逐節核准，等待書面規格最終審閱
- 適用範圍：Web 原型玩法重構、辦公室篇內容、美術生產數量
- 核心定位：合法成人分級的 R18 漫畫編排遊戲

## 1. 目標

把現有《大樓管理員》原型改造成單一六格漫畫編排遊戲。玩家表面上是
用人物、場景與道具卡創作漫畫，實際上是在完成預先設計的完美路線、
人物支線或無效排列。

本設計取代下列舊方向：

- 大樓、房間、管理員與超自然謎團。
- 12 張發牌、選 6 張的房間流程。
- 成人內容開關與安全版素材。
- 以大量文字解釋卡片效果、數值與劇情。

現有程式與舊文件在新實作完成前仍保留；本文件是下一輪重構的需求來源，
不是已完成實作的描述。

## 2. 核准決策

| 項目 | 決策 |
|---|---|
| 畫面 | 使用玩家提供的直式六格漫畫版型；第一格與第六格固定，中間四格可編排 |
| 第一格 | 固定開場美術與少量對話，交代辦公室事件 |
| 中間四格 | 卡槽數依序為 `2 / 1 / 2 / 3`，總共放置 8 張卡 |
| 提示 | 第 2 格淡示「人物＋人物」；第 4 格淡示「場景＋道具」；提示不構成限制 |
| 第六格 | 提交前完全遮蔽，不顯示人物、畫面或結局線索 |
| 牌庫 | 人物 5 張、場景 4 張、道具 4 張，共 13 張 |
| 使用限制 | 每張卡只能使用一次；必須填滿八個位置才能提交 |
| 排列 | 漫畫格順序與同格由左到右順序都影響劇情 |
| 完美結局 | 唯一指定的八卡排列；播放完整 R18 漫畫 |
| 支線結局 | 恰好選出兩名不同人物但未命中完美排列；播放配對專屬 R18 支線 |
| 無效結局 | 人物少於兩張、超過兩張、人物重複或卡片重複；只顯示文字並要求重選 |
| 成人分級 | 只有進入遊戲前的 18 歲確認；沒有成人內容開關或安全版資源 |
| 文字策略 | 圖像優先；對話短、直接，所有文字由程式疊加，不畫死在美術內 |

## 3. 核心流程

1. 玩家通過 18 歲確認。
2. 遊戲直接開啟辦公室篇，不顯示大樓或房間選單。
3. 第一格播放固定開場。
4. 玩家在第 2 至第 5 格放入八張不重複卡片。
5. 玩家可拖放、點選放置、移動或移除卡片；兩個提示格不限制卡別。
6. 第六格在整個編排階段維持遮蔽。
7. 玩家提交後，卡片 UI 消失，卡面轉成單幅、左右雙幅或三連幅漫畫。
8. 第 2 至第 5 格依序揭露短對話，最後才翻開第六格。
9. 完美與支線接續各自的成人漫畫頁；無效結局只顯示原因文字。
10. 無效結局返回編排時保留原排列，讓玩家直接調整。

玩家體驗上的重點不是「猜結局」，而是看見自己放下的素材依序成為漫畫，
直到最後一格才知道完成了哪條預製路線。

## 4. 六格版型

依玩家提供的參考圖使用直式漫畫頁：

| 格位 | 視覺比例 | 功能 |
|---|---|---|
| 第 1 格 | 左上橫幅大格 | 固定開場 |
| 第 2 格 | 右上近方格 | 2 個卡位；淡示人物＋人物 |
| 第 3 格 | 左中直格 | 1 個卡位；無提示 |
| 第 4 格 | 右中橫格 | 2 個卡位；淡示場景＋道具 |
| 第 5 格 | 左下橫格 | 3 個卡位；無提示 |
| 第 6 格 | 右下近方格 | 提交前遮蔽；最後揭露結局 |

卡片放入多卡格時先保持卡片外觀。提交後移除邊框、稀有度、卡名與操作
按鈕，再把卡圖裁切成漫畫內部分鏡。這樣不需要為所有排列重畫第 2 至
第 5 格，同時保留「玩家創作漫畫」的視覺感。

## 5. 辦公室篇

### 5.1 篇章標題

《鎖門之後》

### 5.2 固定開場

公司併購案簽約前夜，最終版合約被留在老闆的私人辦公室。兩名新進職員、
兩名秘書仍在主管樓層加班，暫時離開的老闆也可能隨時返回。第一格用一幅
群像與兩至三句短對話建立人物、機密文件及空辦公室，不指定玩家接下來
必須跟隨誰。

### 5.3 成人調性

整體採俗辣、直球、快速進入成人橋段的低價 R18 漫畫節奏：

- 辦公室、權力關係與「不該在這裡發生」的禁忌感是主要賣點。
- 鋪陳短，卡片排序完成工作事件後迅速轉入人物慾望。
- 對話直接、挑逗、略帶誇張，不使用長篇心理獨白。
- 完美與支線都可以有 R18 內容；結局等級代表路線完整度，不代表色情尺度。
- 所有人物在本作品中均明確為成年人，親密互動呈現雙方自願。

## 7. 結局判定

### 7.1 讀取順序

判定器依下列順序讀取八張卡：

```text
第2格左 → 第2格右
→ 第3格
→ 第4格左 → 第4格右
→ 第5格左 → 第5格中 → 第5格右
```

任何位置交換都會產生不同的劇情指紋。

### 7.2 唯一完美指紋

```text
第2格：男漂泊者 → 長離
第3格：主管樓層走廊
第4格：老闆私人辦公室 → 萬用門卡
第5格：併購合約 → 百葉窗遙控器 → 威士忌酒具
```

只有八個位置全部命中才進入完美結局。男漂泊者與長離反向放置、場景或
道具位置錯誤，都降為該人物組合的支線。

### 7.3 判定優先順序

```text
八個位置完全等於完美指紋
  → perfect

否則，八張卡中恰好有兩張不同人物卡，且沒有重複卡
  → side，依人物組合選擇支線美術

否則
  → invalid
```

人物在八卡中的第一次與第二次出現順序形成有方向的劇情關係，用來決定
主動方、對話及中間格閱讀方式。美術以不分方向的配對鍵載入，因此 20 種
有方向的人物排列共用 10 組配對結局美術。

### 7.4 支線配對

| 人物組合 | 支線方向 |
|---|---|
| 男漂泊者 × 女漂泊者 | 同期競爭者共同掩蓋工作失誤 |
| 男漂泊者 × 相里要 | 新人與男性秘書交換主導權 |
| 男漂泊者 × 長離 | 錯過完美步驟後，在其他辦公區域發展的短篇 |
| 男漂泊者 × 鳴式（老闆） | 深夜忠誠測試轉成私下交易 |
| 女漂泊者 × 相里要 | 電梯停駛後的保護與反客為主 |
| 女漂泊者 × 長離 | 女性前輩替新人承擔風險的百合短篇 |
| 女漂泊者 × 鳴式（老闆） | 新人用談判反轉原本的權力位置 |
| 相里要 × 長離 | 兩名秘書長期競爭後的私下和解 |
| 相里要 × 鳴式（老闆） | 多年隱藏關係在簽約夜重新確認 |
| 長離 × 鳴式（老闆） | 既有默契因機密合約產生裂縫與修復 |

各支線共用固定四幅成人漫畫，但根據兩張人物卡的先後順序切換第一句
對話、主動方描述與畫面閱讀起點。

## 8. 結局展演

### 8.1 完美結局

- 第六格：1 幅專屬關鍵畫面。
- 後續：3 張四格漫畫頁，共 12 幅 R18 畫面。
- 節奏：進入辦公室、完成合約事件、明確確認意願、成人展演、事後收束。

### 8.2 支線結局

- 每組人物配對有 1 幅專屬第六格。
- 每組接續 1 張四格漫畫頁，共 4 幅 R18 畫面。
- 十組配對共 10 幅第六格與 40 幅後續畫面。

### 8.3 無效結局

- 第六格只顯示文字與重新編排按鈕。
- 不製作結局 CG，不解鎖成人漫畫。
- 文案指出故事缺少第二名人物或人物過多，但不公開完美排列。

## 9. 程式架構

### 9.1 主要單元

| 單元 | 責任 |
|---|---|
| `AgeGate` | 一次性 18 歲確認 |
| `ComicBuilderScreen` | 六格頁面、卡片牌庫、拖放與鍵盤操作 |
| `ComicPanelSlot` | 單卡、雙卡、三卡排列與提交後漫畫化 |
| `CardTray` | 人物／場景／道具分頁及使用狀態 |
| `route-resolver` | 以八卡序列回傳 `perfect`、`side` 或 `invalid` |
| `RevealSequence` | 第 2 至第 6 格的依序揭露 |
| `EndingReader` | 完美三頁或支線一頁漫畫閱讀 |
| `episode-schema` | 驗證卡片、槽位、完美指紋、配對結局與資源 |

### 9.2 資料流

```text
辦公室篇 JSON
  → schema 驗證
  → 13 張牌庫與 8 個卡位
  → 玩家排列
  → route-resolver
      ├─ perfect → 完美第六格 → 12 幅後續漫畫
      ├─ side    → 配對第六格 → 4 幅支線漫畫
      └─ invalid → 文字第六格 → 保留排列重選
```

路線判定必須是沒有 UI 相依的純函式。畫面只消費判定結果，不自行推算
人物數量或完美條件。

### 9.3 儲存

新原型使用新的儲存鍵保存：

- 18 歲確認。
- 當前八卡排列。
- 已解鎖的完美與支線配對。

舊大樓原型的 localStorage 資料不刪除、不改寫，也不嘗試遷移成新路線。

## 10. 錯誤與恢復

- 內容 JSON 無效時顯示可重試錯誤，不開啟空白遊戲頁。
- 不允許提交未填滿的八個位置。
- UI 阻止重複卡；判定器仍把重複卡視為無效，避免損壞存檔繞過規則。
- 揭露動畫中禁止修改排列。
- 資源載入失敗時保留結局 ID，提供重試，不重新判定成其他結局。
- 無效結局返回後保留八卡位置，不強迫玩家從空白重新開始。

其中 82 份是遊戲資源，5 份是角色設定表。

### 11.2 第一批

第一批只需要 18 份：

- 5 份角色設定表。
- 5 張人物卡立繪。
- 4 張場景卡背景。
- 4 張道具卡透明圖。

程式重構先使用灰階佔位圖完成互動，不等待全部 87 份素材。

### 11.3 技術要求

- 所有圖片使用 sRGB。
- 主圖長邊至少 2048 px。
- 道具圖使用透明背景 PNG。
- 圖片內不得包含對話、卡名或 UI。
- 人物臉部、手部及關鍵道具需位於中央 70% 安全區，以支援不同漫畫格裁切。
- 同一配對的第六格與後續四格必須維持服裝、髮型、時間與場景連續性。
- 正式商用素材不得沿用暫代角色的受保護名稱或可識別造型。

## 12. 驗證

### 12.1 自動化

- 完美八卡指紋只回傳 `perfect`。
- 任一位置交換都不再是完美結局。
- 所有 10 組人物配對在非完美排列下都回傳對應 `side`。
- 反向人物順序保留方向資料，但載入相同配對美術。
- 0、1、3、4 或 5 張人物卡都回傳 `invalid`。
- 重複卡、缺卡與未知卡 ID 都不可進入有效結局。
- 提交前第六格沒有結局圖片或可推測結局的替代文字。
- 兩個提示格接受任何卡別。
- 卡片放置後不能在其他位置再次使用。
- 無效結局返回後排列保持不變。

完成實作後必須執行：

```powershell
npm --prefix prototype-web run check
```

### 12.2 人工 QA

依專案規則，人工 QA 只能使用部署到 GitHub 的線上預覽，且必須記錄：

- 自動化測試通過的精確 commit。
- 部署該 commit 的 GitHub 預覽 URL。
- URL 已成功開啟。
- 六格版型、手機與桌面裁切、第六格遮蔽、卡片操作及所有結局類型。

## 13. 非目標

- 本規格階段不修改 React、內容 JSON 或現有測試。
- 第一輪實作不製作正式美術。
- 不建立即時人物／場景／道具圖層合成器。
- 不為所有八卡排列製作獨立漫畫。
- 不保留大樓、房間、管理員或舊成人內容切換介面。
- 不在沒有精確受測 commit 與 GitHub 預覽時交付人工 QA。
