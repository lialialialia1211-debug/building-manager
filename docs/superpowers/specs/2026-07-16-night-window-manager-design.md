# 《夜窗管理員》Steam 體驗版遊戲設計規格

- 日期：2026-07-16
- 狀態：已完成逐段設計確認，待書面規格最終審閱
- 產品類型：Steam 單機成人向劇情推理／動態漫畫遊戲
- 目標版本：60～90 分鐘 Steam 體驗版

## 1. 產品摘要

《夜窗管理員》是一款以漫畫分鏡選擇為核心的成人向劇情推理遊戲。玩家扮演大樓的夜班管理員，從管理室觀察午夜後異常亮起的房間，進入由大樓生成的「事件漫畫頁」，並從三個隱藏對白的候選分鏡中逐格選擇，改變成年住戶的故事。

遊戲沒有立即失敗或無效路線。每種選擇都必須形成可閱讀的完整劇情；特定選擇、角色狀態與跨房線索會通往共同謎團或特殊親密結局。核心樂趣是觀察候選畫面中的人物動作、道具、燈光與環境線索，推測選擇後果，再透過重玩理解故事全貌。

## 2. 設計目標

### 2.1 核心目標

1. 玩家只看候選分鏡畫面，也能辨認三個不同的行動意圖。
2. 每次選擇都能產生有意義的中間劇情，不存在單純的錯誤選項。
3. 第一次完成房間後，玩家願意利用已讀快轉探索其他結局。
4. 兩個體驗版房間各自能完整收束，同時讓玩家察覺共同的大樓謎團。
5. 即使不以成人內容作為主要動機，故事推理與分支收集仍具吸引力。

### 2.2 非目標

體驗版不包含：

- 線上連線、多人、抽卡或服務型營運機制。
- 完整骨架動畫、Live2D 場景或逐鏡頭 2D 動畫。
- 六個正式版房間的完整內容。
- Steam 成就、線上排行榜或依賴伺服器的功能。
- 完整語音演出；體驗版以環境音、音效、配樂及必要語氣聲為主。

引擎選擇不屬於本產品設計規格的決策範圍；實作規劃必須依團隊熟悉度、動態漫畫工具鏈與 Steam 匯出需求另行決定。

## 3. 內容與分級原則

- 所有登場角色在角色資料與劇情設定中均明確為成年人。
- 成人與親密互動只描寫成年人之間自願、同意的關係。
- 遊戲不設年齡選擇或年齡確認流程。
- 成人內容預設啟用；玩家可在設定中關閉。
- 關閉成人內容時，系統改播替代分鏡或淡出版本，但保留故事結果、共同線索與通關資格。
- 親密路線先在主要漫畫頁形成完整的親密結局，再解鎖可獨立重播的完整成人向動態漫畫場景。

## 4. 體驗版範圍

### 4.1 內容規模

- 一層大樓地圖。
- 兩個可完整遊玩的房間。
- 每個房間包含固定開頭、5～7 個玩家待填分鏡及一個固定結尾錨點。
- 固定結尾錨點代表所有路線最後都回到同一個收束事件與漫畫位置；系統依結局判定套用主線、普通／意外或特殊親密版本的對白、色調及後續解鎖。
- 每個選擇節點提供三個候選分鏡。
- 每個房間提供三個主要結局：
  - 主線結局。
  - 普通／意外結局。
  - 特殊親密結局。
- 回想圖鑑收錄已解鎖分鏡、結局與親密場景。
- 其餘四個正式版房間只顯示輪廓、門牌或角色剪影，不提供可玩內容。

### 4.2 遊玩時間

- 首次完成兩房的目標時間：40～50 分鐘。
- 重玩並收集主要分支的總體驗時間：60～90 分鐘。
- 已讀快轉必須讓第二次之後的單房遊玩顯著短於首次遊玩。

### 4.3 內容產量上限

為避免動態分支造成內容量失控：

- 每房一次流程只會選入 5～7 個中間分鏡。
- 每房可選分鏡的美術內容以 18～30 格為目標，硬上限為 30 格。
- 分支必須在部分節點重新匯流；不得為每一條完整排列製作完全獨立的後續。
- 每房維持三個主要結局，中途差異透過分鏡變體、對白、狀態與背景線索表現。

## 5. 世界觀與玩家身分

玩家是新任夜班大樓管理員。午夜後，大樓部分窗戶會異常亮起，管理室同時出現相應住戶的「事件漫畫頁」。漫畫不是監視器錄影，而是大樓將住戶可能發生的未來轉化成分鏡。

玩家填入分鏡後，對應事件便朝該方向發展。大樓為何能展示並改寫可能未來，住戶與玩家起初都不知道。公共電路、反覆出現的神祕符號及圖紙上不存在的房間，共同構成正式版主線謎團。

## 6. 核心遊戲循環

1. 玩家在管理室查看大樓外觀、亮燈房間、解鎖狀態及完成進度。
2. 玩家選擇已解鎖房間，查看成年角色資料、事件簡介與已發現線索。
3. 漫畫頁播放固定開頭，依閱讀順序聚焦第一個空白分鏡。
4. 畫面下方顯示三個候選分鏡；候選只顯示畫面，不顯示對白、數值或結局傾向。
5. 玩家選擇一格後立即鎖定，不可撤回。
6. 系統先完成自動存檔，再將分鏡嵌入漫畫頁。
7. 完整對白與動態演出揭曉，並短暫顯示角色狀態變化。
8. 故事引擎依當前節點、已選內容、角色狀態及跨房旗標產生下一組三個候選。
9. 重複選擇，直到填滿 5～7 格。
10. 系統判定結局，播放固定結尾錨點所對應的結局版本。
11. 結算頁顯示新分鏡、線索、狀態結果及回想解鎖內容。
12. 玩家返回大樓，可進入其他房間或重玩已完成房間。

## 7. 候選分鏡規則

### 7.1 顯示內容

候選格必須讓玩家從以下元素推測意圖：

- 角色姿勢、視線與表情。
- 手持物、門窗、燈光及場景變化。
- 角色之間的距離與相對位置。
- 漫畫構圖、速度線、陰影或畫面焦點。

候選格不得顯示：

- 完整對白。
- 數值增減。
- 「主線」、「親密」或「正確」等結果標籤。
- 可直接暴露結局條件的顏色分類。

### 7.2 選入後揭曉

選入漫畫頁後才顯示：

- 完整分鏡與對白。
- 動態漫畫演出。
- 好感、信任、親密傾向等狀態的方向性變化。
- 必要的事件旗標或線索取得提示。

預設只顯示「信任上升」等定性提示，不顯示精確數字。設定中可開啟精確數值，以方便重玩與收集。

### 7.3 選擇承諾

- 選入後立即鎖定，當次流程不可撤回或倒帶。
- 關閉遊戲再重新啟動，仍從已鎖定選擇後繼續。
- 玩家必須完成當次故事後，才能從房間開頭建立新的重玩流程。

## 8. 分支與結局設計

### 8.1 分支結構

故事圖由以下節點構成：

- 固定開頭節點。
- 三選一選擇節點。
- 分鏡揭曉與演出節點。
- 狀態／旗標套用節點。
- 分支匯流節點。
- 結局判定節點。
- 固定結尾錨點及其三個條件式演出版本。

每次選擇都必須有合法後續。分支可造成不同對白、角色狀態、背景物件與中間事件，但必須適時匯流，以維持每房三個主要結局的內容規模。

「固定結尾」不代表三條路線播放完全相同的內容。所有路線會抵達同一個收束事件與漫畫位置，但系統依主要結局切換該位置的對白、畫面差分、色調、線索及後續回想解鎖。

### 8.2 狀態

核心角色狀態為：

- 好感：角色對彼此的正面情緒與接近意願。
- 信任：角色願意揭露資訊、接受協助或相信對方的程度。
- 親密傾向：當前情境是否自然朝自願親密關係發展。

結局不得只由單一狀態的高低決定。特殊親密結局必須同時滿足：

- 指定關鍵選擇或事件旗標。
- 房間資料定義的角色狀態組合。
- 劇情中明確建立的成年身分與相互同意條件。

各房間可定義自己的狀態門檻；狀態資料以可配置的整數與條件式保存，不在核心程式中寫死全域門檻。

### 8.3 三種主要結局

**主線結局**

- 解決或推進該房間事件。
- 提供大樓共同謎團的有效線索。
- 可影響另一房的背景、燈光、聲音或候選內容。

**普通／意外結局**

- 完整收束當次房間事件。
- 不要求揭露共同謎團。
- 必須具有自身的情緒價值，不能只是較差版本的主線結局。

**特殊親密結局**

- 建立在成年角色之間自願且具前置發展的關係上。
- 主要漫畫頁先完成親密結局。
- 結算後解鎖獨立的完整成人向動態漫畫場景。

### 8.4 沒有失敗路線

- 不設中途任務失敗。
- 不因數值不足突然中斷故事。
- 所有合法選擇都能抵達至少一個完整結局。
- 不符合主線或親密條件時，應進入普通、意外或其他有意義的分支收束。

## 9. 體驗版故事

### 9.1 房間 A：〈停電之夜〉

定位：教學房間，候選畫面的因果與視覺線索較直接。

內容：

- 一名成年住戶在停電後面臨訪客、異常配電箱與神祕留言。
- 選擇教導玩家觀察人物動作、工具、門口及室內光源。
- 主線結局揭露大樓電路中存在圖紙未記載的迴路。
- 普通／意外結局完整收束當晚事件，但錯過共同謎團的關鍵資訊。
- 特殊親密結局描寫成年角色在建立信任與同意後的關係發展，並解鎖獨立成人回想。

### 9.2 房間 B：〈牆後的聲音〉

定位：進階房間，結果較不直接，鼓勵玩家綜合道具、燈光與人物反應推理。

內容：

- 一名成年住戶每晚聽見牆後傳來聲音，並與另一名成年住戶產生交集。
- 主線結局發現聲音來自大樓圖紙上不存在的空間。
- 普通／意外結局將聲音理解或處理為一般住戶事件，形成另一種完整收束。
- 特殊親密結局建立在關係、信任、關鍵選擇與相互同意條件上。

### 9.3 跨房連動與體驗版結尾

- 房間 A 的部分選擇會改變房間 B 的燈光、聲音、背景物件或可見線索。
- 跨房變化提供額外資訊，但不得封鎖房間 B 的三個主要結局。
- 初始同時開放兩個體驗版房間，玩家可自行決定先後順序。
- 完成兩個主線結局後，大樓地圖短暫亮起圖紙上不存在的「第六房間」。
- 畫面顯示其餘四個房間的輪廓與角色剪影，作為正式版群像故事預告。

## 10. 介面資訊架構

### 10.1 設定／啟動畫面

- 不顯示年齡選擇或年齡確認。
- 成人內容預設啟用，可在設定中關閉。
- 提供音量、文字速度、視窗／全螢幕、解析度及精確數值顯示選項。

### 10.2 管理室／大樓地圖

顯示：

- 大樓外觀與房間窗戶。
- 房間亮燈、可進入、未開放及已完成狀態。
- 每房三個結局的完成度，但未解鎖結局只顯示未知標記。
- 異常電路、聲音或第六房間等共同謎團提示。
- 回想圖鑑與設定入口。

### 10.3 房間任務頁

顯示：

- 成年角色資料。
- 事件簡介。
- 已發現線索。
- 結局收集度。
- 開始或重玩按鈕。

不得提前顯示未發現的結局條件。

### 10.4 漫畫遊玩頁

Steam PC 橫向介面：

- 左側或中央：完整漫畫頁與目前聚焦的空白格。
- 右側：角色狀態、已取得線索及必要操作提示。
- 下方：三個候選分鏡。

候選格在常見桌面解析度與 Steam Deck 畫面上都必須能清楚辨認人物姿勢與關鍵道具。

### 10.5 結算頁

顯示：

- 結局名稱與類型。
- 新取得的共同線索。
- 最終角色狀態。
- 新解鎖分鏡、結局與回想。
- 重玩、前往另一房或返回大樓的操作。

### 10.6 回想圖鑑

- 依房間分類已解鎖分鏡、三種結局與親密場景。
- 未解鎖內容只顯示剪影或未知標記。
- 可重播單一分鏡演出、完整結局及已解鎖成人向動態漫畫。
- 關閉成人內容後，成人回想入口隱藏或改為替代版本。

## 11. 動態漫畫演出規格

遊戲始終以漫畫頁為主要舞台，不切換成完整角色動畫模式。

可使用的演出：

- 分鏡滑入、翻頁、墨水展開或紙張拼合。
- 背景、角色與前景分層造成的輕微視差。
- 鏡頭推近、拉遠、平移及焦點轉移。
- 眨眼、嘴型、表情差分及少量局部動作。
- 震動、速度線、粒子、燈光閃爍及色調轉換。
- 對白框依節奏逐一顯示。
- 環境音、動作音效及配樂變化。
- 關鍵選擇造成漫畫格尺寸、邊框、排列或色彩變化。

不得將體驗版製作目標擴張為完整 2D 動畫。成人場景沿用相同的分層素材與動態漫畫演出系統。

## 12. 已讀與重玩

- 系統以分鏡編號及對白變體記錄已讀狀態。
- 重玩時預設自動快轉已讀演出。
- 遇到未讀分鏡、未讀對白變體、新線索或新結局時，自動恢復正常速度。
- 玩家仍需在每個選擇點主動選擇，快轉不得自動代選。
- 玩家可手動暫停快轉或在設定中關閉自動快轉。

## 13. 系統架構

本遊戲採資料驅動架構，故事、美術、演出與核心程式分離。

### 13.1 房間管理器

負責：

- 房間可用與完成狀態。
- 大樓窗戶亮燈表現。
- 跨房線索及旗標。
- 體驗版第六房間預告條件。

### 13.2 故事分支引擎

負責：

- 載入當前故事節點。
- 依狀態、旗標與前置節點篩選合法候選。
- 確保每個選擇節點提供三個不同候選。
- 前往下一分支或匯流節點。

### 13.3 漫畫演出器

負責：

- 漫畫頁排版與空白格聚焦。
- 分鏡嵌入、對白與演出時間軸。
- 分層視差、局部動畫、音效與轉場。
- 已讀快轉及遇到新內容時恢復正常速度。

### 13.4 結局判定器

負責：

- 讀取關鍵選擇、角色狀態、線索及旗標。
- 按房間資料定義的優先順序判定唯一主要結局。
- 解鎖共同線索與回想內容。

結局條件有重疊時，優先順序固定為：

1. 特殊親密結局。
2. 主線結局。
3. 普通／意外結局。

故事資料檢查器必須警告條件重疊，內容設計仍應盡量讓各結局條件互斥。

### 13.5 進度與存檔系統

記錄：

- 當前房間、故事節點及已鎖定選擇。
- 角色狀態與事件旗標。
- 已讀分鏡與對白變體。
- 已完成結局、共同線索與回想解鎖。
- 成人內容、精確數值及已讀快轉等設定。

### 13.6 內容資料庫

每個漫畫分鏡使用唯一編號，並連結：

- 預覽素材。
- 完整素材與分層資源。
- 對白。
- 演出時間軸。
- 狀態變化。
- 事件旗標。
- 下一節點或匯流點。
- 成人內容開關時的替代素材或替代節點。

## 14. 資料流程

```text
進入房間
→ 載入固定開頭與目前故事節點
→ 依條件篩選三個合法候選
→ 玩家選擇
→ 立即鎖定並自動存檔
→ 套用角色狀態與事件旗標
→ 播放完整動態漫畫分鏡
→ 前往下一節點或匯流點
→ 填滿 5～7 個中間分鏡
→ 判定主要結局
→ 播放固定結尾錨點的對應版本
→ 解鎖線索、回想及跨房狀態
→ 返回大樓
```

## 15. 存檔規則

- 玩家選入分鏡後，先完成自動存檔，再開始揭曉演出。
- 重新啟動遊戲時，從已鎖定選擇後的演出或下一安全節點繼續。
- 當次房間流程不可透過重新啟動撤回選擇。
- 房間結束後才能從開頭建立新的重玩流程。
- 收集進度永久保留，不因重玩覆蓋。
- 保留最近兩份自動備份。
- 存檔格式包含版本號；版本變更時先轉換副本，成功後才覆蓋正式存檔。
- 轉換失敗時自動恢復最近可讀備份，並保留損壞檔供除錯。

## 16. 錯誤處理

- 若故事節點無法產生三個合法候選，停止進入該節點，改載入房間資料指定的安全匯流節點並記錄錯誤。
- 若安全匯流節點也無效，返回房間開頭前的安全存檔，不得生成空白結局。
- 圖片、音效或演出資源遺失時使用具資源編號的替代素材，讓測試人員能辨識問題。
- 單一非必要音效或局部動畫失敗時，跳過該效果並繼續劇情。
- 成人替代節點缺失時，不得播放成人資源；改以安全淡出版本完成相同故事結果。

## 17. 測試策略

### 17.1 故事圖自動驗證

自動檢查：

- 每個選擇節點恰好有三個合法候選。
- 三個候選編號與預覽不得重複。
- 每個節點都有合法後續或結局。
- 不存在無限循環、孤立節點或不可達結局。
- 每房三種主要結局各自至少有一條可達路線。
- 所有合法路線均能在 5～7 次選擇內結束。
- 成人開啟與關閉版本都能走完整流程。
- 跨房旗標不會封鎖任何主要結局。

### 17.2 存檔測試

- 選擇後、演出前強制關閉。
- 演出中強制關閉。
- 存檔損壞與備份恢復。
- 版本更新與存檔轉換。
- 房間結束後重玩及收集進度保留。

### 17.3 已讀快轉測試

- 全已讀路線能持續快轉。
- 遇到新分鏡、新對白變體、新線索或新結局時恢復正常速度。
- 快轉期間仍停在選擇點等待玩家操作。
- 關閉自動快轉後所有內容以正常速度播放。

### 17.4 介面與相容性測試

- 常見 16:9 PC 解析度。
- 視窗、無邊框及全螢幕模式。
- 滑鼠操作。
- Steam Deck 的基本控制、字體可讀性與候選格辨識度。
- 成人內容開啟與關閉。
- 精確數值顯示開啟與關閉。

### 17.5 內容可讀性測試

每組候選分鏡至少進行一次不顯示對白的玩家測試。測試者應能：

- 說出三個候選的大致行動意圖。
- 指出造成判斷的畫面線索。
- 在揭曉後認為結果與畫面線索合理相關。

若多數測試者無法區分候選，優先調整姿勢、構圖、道具或光線，不以加入文字標籤解決。

## 18. 體驗版驗收標準

體驗版完成必須同時符合：

1. 兩個房間都能從固定開頭完整遊玩至三種主要結局。
2. 每次流程包含 5～7 次不可撤回的三選一分鏡選擇。
3. 所有合法選擇都能通往完整結局，不出現流程中斷或無內容收束。
4. 候選分鏡不顯示對白時，玩家仍能辨認不同意圖。
5. 選入後正確揭曉完整對白、動態漫畫演出與狀態變化。
6. 已讀快轉能縮短重玩時間，並在新內容出現時恢復正常速度。
7. 成人內容開啟與關閉皆可完整通關。
8. 完成兩房主線結局後，正確播放第六房間亮起的體驗版結尾。
9. 一般玩家首次完成約需 40～50 分鐘，收集主要內容約需 60～90 分鐘。
10. 故事圖、存檔、回想與跨房旗標通過自動測試及人工流程測試。

## 19. 主要風險與控制方式

### 候選分鏡難以理解

以無對白可讀性測試驗證，優先修改畫面語言，不用結果文字補救。

### 分支內容量膨脹

限制每房最多 30 個可選分鏡，使用明確匯流點並固定三個主要結局。

### 數值壓過劇情推理

預設只顯示方向性變化；精確數值為可選設定，結局同時檢查關鍵選擇與狀態組合。

### 成人獎勵壓過核心玩法

主線與普通結局都必須提供完整情緒收束及共同謎團價值；成人內容是特殊路線的延伸，不是唯一有效回饋。

### 動畫成本失控

統一使用動態漫畫系統、分層素材及局部差分，不為單一結局建立另一套完整動畫管線。

## 20. 後續正式版擴充方向

正式版預計擴充為六個房間的成年角色群像：

- 各房具有獨立事件及三個主要結局。
- 角色會互相客串或透過傳聞、道具與公共空間產生連動。
- 半開放式解鎖房間。
- 指定主線及線索條件解鎖不存在的第六房間與共同終章。
- 新增房間主要透過內容資料與素材擴充，不修改核心選格、分支、演出及存檔架構。

## 21. Web-first 驗證策略

正式遊戲引擎移植前，先製作瀏覽器可玩的 Web 原型，以縮短玩法、內容與美術驗證時間。

Web 原型必須實作：

- 大樓地圖、兩個房間、三選一漫畫格、分支匯流及每房三種主要結局。
- 好感、信任、親密傾向、跨房旗標、已讀快轉、本機存檔與回想圖鑑。
- 成人內容開關及安全替代版本。
- 1280×720、1920×1080 與 1280×800 的響應式版面。
- 無對白候選辨識測試、完整路線測試及本機匿名遊玩事件紀錄。

Web 與正式引擎共用下列資料契約：

```text
content/
├── characters.json
├── rooms/
│   ├── room_a_blackout.json
│   └── room_b_wall.json
├── gallery.json
└── asset-manifest.json
```

Web 驗證階段不承諾最終引擎，也不製作 Steam 匯出、Steamworks 整合或正式版完整動畫管線。只有在玩法、美術與時間目標通過驗收後，才制定 Godot 移植計畫。

## 22. 美術量產關卡

美術採兩階段交付：

1. **風格鎖定包**：先確認四名成年角色的一致性、兩個房間的環境語言、無對白三選一的可辨識度及 3 秒動態漫畫效果。
2. **完整 Web 原型包**：風格鎖定後，才量產兩房全部候選分鏡、開場、結局、親密／安全替代場景、背景、道具與 UI。

完整數量、人物姿勢、解析度、檔名、分層方式及演出秒數，以 `docs/art/2026-07-16-web-prototype-art-production-spec.md` 為唯一生產依據。
