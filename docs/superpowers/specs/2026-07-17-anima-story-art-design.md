# 《大樓管理員》Anima 劇情與美術設計

- 日期：2026-07-17
- 狀態：討論內容已逐節核准，等待書面規格最終審閱
- 適用範圍：Web 原型正式美術前製、48 張候選卡、八支 12 秒結局影片
- 生產工具：本機 ComfyUI；正式靜態圖以 Anima Aesthetic v1.1 為基準
- 完整生產包：[`docs/art/2026-07-17-anima-production-package/`](../../art/2026-07-17-anima-production-package/README.md)

## 1. 目標

把已完成自動化驗證的 24 選 12、選 6 遊戲流程，轉成可直接交給本機 ComfyUI 生產的劇情與美術規格。規格必須同時回答：

- 每房 24 張候選卡分別發生什麼事。
- 每張卡需要哪一種人物姿勢、鏡頭、道具與光線。
- 任意六張、任意排列後，劇情為何仍能成立。
- 六種結局如何變成八支 12 秒影片。
- 成人內容開啟與關閉時如何分流，且維持相同感情與解鎖結果。
- Anima／ComfyUI 如何鎖定角色、姿勢與生產紀錄。

本文件與生產包是設計交付，不會自行改變 `content/`、Web 原型行為或目前 GitHub Pages QA build。

## 2. 已核准決策

| 項目 | 決策 |
|---|---|
| 候選卡 | 每房保留 24 張；每局隨機發 12 張，玩家選 6 張並自由排列 |
| 劇情結構 | 預言式因果積木：大樓讓玩家選定的六個未來片段依排列順序成真 |
| 世界 | 不對應真實國家的低魔架空都市；現代生活存在，大樓與第六房間具超自然意志 |
| 角色 | 保留林雨薇、陳皓然、許安寧、周衍及既有年齡；全員明確為成年人 |
| 視覺 | 清線賽璐璐動畫；深色輪廓、兩階陰影、少量高光、清楚剪影 |
| 靜態圖工具 | 本機 ComfyUI；草稿可用 Anima Turbo，正式圖使用 Anima Aesthetic v1.1 |
| 結局影片 | 六個結局均為 12 秒完整影片；普通／主線共四支，親密成人／安全版本共四支，總計八支 |
| 成人內容 | 親密結局直接分級；成人開啟時播放明確成人版本，關閉時播放安全版本 |
| 影片生產 | 本規格提供故事板、姿勢與關鍵幀；實際影片模型與生成工作流由美術負責人決定 |

## 3. 世界與核心規則

故事發生在低魔架空都市「暮環市」，舞臺是居民俗稱「夜窗大樓」的老式集合住宅。城市生活接近現代，但少數建築會累積人的記憶、約定與未完成的選擇。

午夜後，管理室會亮起不存在於圖紙上的黃色窗格，並生成十二張可能未來的事件分鏡。玩家選定六張後，大樓讓它們依排列順序成真。

不可變規則：

1. 大樓只能放大角色原本可能作出的選擇，不能控制意志。
2. 每張候選卡必須是能獨立成立的事件，不依賴固定上一張或下一張。
3. 黃色六格符號指向會在建築內移動的記憶核心「第六房間」。
4. Room A 的異常迴路是第六房間漏出的記憶電流。
5. Room B 的牆後聲音是第六房間移動時留下的回聲。
6. 主線結局推進共同謎團；普通結局處理當晚危機；親密結局建立兩名成年角色的關係。
7. 成人版與安全版不得改變線索、感情結果或解鎖資格。

## 4. 設計組件

完整生產包拆成七個可獨立使用的單元：

1. 世界與視覺 Bible：定義幻想規則、賽璐璐語言、色彩及構圖。
2. 角色 Bible：固定四名角色的臉、髮型、服裝、身形及姿勢語言。
3. Room A 卡片表：24 張事件、姿勢、鏡頭、結局傾向及英文 scene prompt。
4. Room B 卡片表：24 張事件、姿勢、鏡頭、結局傾向及英文 scene prompt。
5. 結局影片故事板：八支影片的時間軸、起始姿勢、動作及尾幀。
6. Anima／ComfyUI 規格：模型、參數、prompt blocks、ControlNet 與紀錄欄位。
7. 生產／QA 清單：26 項風格鎖定包、87 張主構圖契約、停止條件及驗收證據。

## 5. 資料流與來源層級

```text
content/ 穩定 ID 與遊戲數值
  → 本生產包的劇情、姿勢與 scene prompt
  → 角色 reference／姿勢控制圖
  → ComfyUI workflow＋Anima 輸出
  → 單張／縮圖／角色一致性驗收
  → content/asset-manifest.json（另立實作計畫後整合）
  → Web 線上 QA
```

來源優先順序：

1. `content/rooms/*.json` 保留卡片 ID、必發卡、數值、旗標及結局判定。
2. 本生產包是新的劇情、美術與 prompt 來源。
3. 舊的 `docs/art/2026-07-16-web-prototype-art-production-spec.md` 僅保留為歷史數量基線。
4. 若生產包與 runtime JSON 的劇情文字不同，先停止整合，另立實作計畫同步內容，不可私自在美術檔名中修正。

## 6. 失敗處理與停止條件

發生以下任一情況即停止該批次：

- 同一角色連續三張無法維持臉型、髮型、服裝或年齡感。
- 十二張牌池中有兩張以上被多數測試者判斷為相同動作。
- 角色手部、道具或身體接觸無法符合故事板。
- 雙人特徵互相污染，且區域控制／分開生成合成仍無法修正。
- 成人版未能清楚表達成年、清醒及雙向同意。
- 安全模式會載入 `/adult/` 資源。
- 圖片只能靠卡片文字才能理解主要動作。

停止後先修正角色 reference、姿勢控制、構圖或 prompt blocks，不繼續堆積待返工素材。

## 7. 驗證方式

- 風格鎖定：先完成 26 項 package，不直接量產全部 87 張主構圖。
- 無對白辨識：五名測試者至少四名能分辨六張代表卡的主要行動。
- 縮圖驗收：`960×540` 與十二張同屏狀態仍能辨識人物姿勢及關鍵道具。
- 一致性：四名角色的固定特徵跨代表卡、成人版與安全版都不得漂移。
- 動態：每段結局影片逐鏡檢查臉部、手部、服裝、背景及持有物連續性。
- 技術：正式資源整合前執行 `npm --prefix prototype-web run check`，並另做 GitHub 線上 QA。

## 8. 非目標

- 本階段不生成正式圖片或影片。
- 不修改目前原型的劇情 JSON、資源載入或 UI。
- 不把 `asset-manifest.json` 從 `greybox` 切換成 `formal`。
- 不解除真人玩家測試、美術驗收或 Godot migration gate。
